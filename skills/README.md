# 测试知识库协作 Skill

让测试团队基于已有资料建立知识库、复用与补充用例，并让新人按指南完成首个真实任务。适合团队在不同项目共同使用，不绑定业务系统、文档平台或用例格式。

## 包含的能力

- 首次确认建库位置与实际需要的结构，再整理指定材料；已有库沿用用户认可的入口，不强建五类目录。
- 依托已有规则和用例输出复用与缺口映射，只补本次差异，保留项目用例格式。
- 自动沉淀已确认且可复用的结论，集中处理不确定项；支持在另行配置的定时任务中执行。
- 优先更新原文、增量索引和按需检索，避免知识库随聊天和日期不断产生重复文件。
- 按每个项目的业务范围筛选资料，管理、通用AI协作资料与工具程序在库外维护。

## 资料范围

每个知识库先明确项目及覆盖模块，根README记录范围与排除项。风控、小程序、商家后台等均可独立使用，也可按用户明确指定的范围组合，不绑定某个公司的目录或业务规则。

| 纳入项目知识库 | 默认在库外维护 |
|---|---|
| 项目业务规则、操作/测试流程、环境与数据方法、用例、需求交付、相关接口与实际证据 | OKR、绩效工时、个人计划、跨项目制度、Prompt/Skill与AI协作案例、个人项目整理、工具程序及依赖 |

项目工具只保留必要使用说明与入口。上下游系统只保留与本项目链路相关的契约及预期，不复制对方整套知识。例如租赁小程序可以按实际范围维护下单、续租和支付知识，风控相关部分保留下单触发与结果承接；不自动导入全部内部策略。

README、协作规则、来源与状态索引和简短维护记录是维持知识库的控制资料，仍按需要保留。已有库发现范围外内容时，只有在用户要求整理后才迁出并修复引用；日常读取或写用例不会自行搬迁文件。

## 安装与使用

Skill 位于 `skills/qa-knowledge-base/`，入口为 [SKILL.md](qa-knowledge-base/SKILL.md)。

下载仓库后，将完整的 `qa-knowledge-base` 文件夹复制到 Codex 的用户技能目录：默认是 `~/.codex/skills/`，配置了 `CODEX_HOME` 时则为该目录下的 `skills/`。也可通过 Codex 的 skill-installer 按仓库地址和 `skills/qa-knowledge-base` 路径安装。其他兼容 SKILL.md 的工具按各自安装约定使用。

在 Codex 中可以直接说：

```text
使用 skill-installer，从 https://github.com/test123604/ai-testcraft 安装 skills/qa-knowledge-base。
```

安装后如当前会话尚未显示该 Skill，重启 Codex 再调用。

示例请求：

```text
使用 $qa-knowledge-base，帮我们建立项目测试知识库，先询问我要建在哪里。

使用 $qa-knowledge-base，把我指定的资料整理到现有知识库中。

使用 $qa-knowledge-base，基于这个需求和现有知识库，梳理可复用用例和覆盖缺口。

使用 $qa-knowledge-base，整理指定记录里已经确认的结论，更新知识库，有冲突的集中列出来。
```

首次交互按“确认位置 → 创建并检查目录 → 询问资料 → 分批整理”推进。已提供的信息不会重复询问；已有知识库优先映射复用。

## 项目知识库目录示例

```text
项目测试知识库/
├── README.md
├── 01-项目与业务/
├── 02-测试指南/
├── 03-测试用例/
├── 04-需求与交付/
└── 05-支撑资料/
```

上面的五类是职责映射示例，不是固定目录要求。也可将规则、测试方法与支撑说明合为“测试指南”，按用途维护操作手册、测试标准、业务规则与问题解答、接口与查询手册、源码参考；需求、用例和报告保留清楚入口。实际文档数量由项目需要决定，图片及必要原件集中作为附件。已有结构不为符合示例而重建。

## 维护方式

知识库只保存沉淀结果，不保存排查流水或逐问题总结。同一规则只维护一处，异常预期、数据准备、来源与版本边界在合并时保留。目录调整同时修复链接、检查程序和调度路径，本地/在线按知识主题映射，图片和原件按用户约定保留，避免全量覆盖远端人工修改。

默认由 AI 判断沉淀价值和归属，直接更新已确认内容；依据不足、相互冲突和未确认的预期进入集中待确认。AI 建议、用户沉默和程序输出不自动成为业务验收依据。

定时执行需要用户另外配置调度任务、资料访问范围及运行时间。Skill 本身不提供调度器，也不保证跨工具读取聊天记录。每轮从各来源上次成功处理位置续接，失败部分保留待重试，不仅处理“昨天”的记录。

此仓库只维护通用 Skill。各项目资料留在团队授权的位置，不上传内部业务材料、凭证或个人敏感数据。

## 验证与边界

本次发布通过 Skill 标准格式检查，并校验本地引用、Markdown 代码块与界面元数据；已在本地安装。尚未在真实团队项目中验证用例覆盖效果或量化提效。安装后可先用虚构资料试运行：指定一个新目录，提供一份包含已确认规则和待确认问题的样例材料，检查分类结果及确认状态是否正确，再接入真实资料。

不依赖此仓库的 RAG 或自动化测试运行环境。文档读取、在线平台访问及定时调度由宿主工具提供，无法访问的资料需要如实报告。维护此 Skill 时修改 qa-knowledge-base/SKILL.md 及相关引用，不在仓库中加入内部项目知识库。

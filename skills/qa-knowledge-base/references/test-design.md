# 检索与用例复用

## 先定位，再读取

优先使用用户指定的知识库入口、项目说明及协作规则；未指定时在当前授权工作区查找入口。存在多个项目且不能判断时只询问必要定位信息。

1. 从根 README 和相关模块/用例索引定位项目、业务模块、当前变更、环境和版本。
2. 根据标题、已有摘要、术语别名、用例 ID 或需求 ID 查找候选，再读相关规则段落和用例正文；索引仅负责定位，不证明覆盖和正确性。
3. 根据业务链路与上下游补查相关模块。候选不足、预期不明或来源冲突时扩大范围；没有搜到不代表没有规则或用例。
4. 默认读取本次需求、相关业务规则、数据方法与候选用例。历史需求、历次报告、原始日志、截图、源码、归档及工具产物，仅在追溯或定位需要时按 ID、版本、批次和证据链接定向读取；当前需求直接引用的证据属于本轮范围。

使用现有文件或平台检索，不每次全库扫描、全库阅读或重建索引。工具不支持目录排除、筛选和局部读取时，用路径和关键词缩小范围，如实说明限制，不宣称已配置不存在的缓存或过滤。

## 确认测试依据

提取变更、业务预期、影响范围、环境/版本、职责及交付要求。分别标识业务验收要求、实现方式和实际观察，不把代码、配置或本次输出直接复制为预期。

当前需求、旧文档、人员说明或执行证据有冲突时，指出具体差异与影响，交由对应角色确认，不只按日期选答案。缺少 PRD 时，可用已确认业务规则及说明形成临时依据，列明缺口，继续完成不依赖未知预期的部分。

## 复用并补差异

阅读候选用例的前置、步骤和预期，交付简短映射表：

| 需求/风险及来源 | 验证角色 | 已有用例 ID/链接 | 调整或新增场景 | 数据与环境依赖 | 待确认项 |
|---|---|---|---|---|---|

按实际情况填写，空表不算完成。

- 已覆盖：引用原用例和适用版本，执行时更换数据，不重写全文。
- 部分覆盖：保留 ID，说明修订部分；只更换数据不必修改用例母版。
- 未覆盖：新增必要场景，沿用项目编号规则。
- 不适用：记录本次不选的原因，不删除原资产。

按变更选择正常、拒绝/失败、边界、条件组合、缺失输入、权限/状态及业务承接；发布、缓存、并发、兼容和上下游仅在相关时展开。不为凑数量拆分，也不把个人职责范围当成整个需求的完整覆盖；关联其他角色的交付结论。

预期来自已确认规则或独立计算。前置数据、操作入口和结果可验证，未知字段、账号、接口、按钮或指标来源标记待准备/确认。

先给复用与缺口结果。评审沿用团队要求，已确认不重复索取；按用户请求交付正式用例，保留主格式，不擅自改成 Markdown、Excel 或 XMind，不维护同内容多份副本。缺少格式处理能力说明限制。

## 编写后同步入库

已明确项目知识库位置，且用户要求为该项目编写或修订用例时，将本次用例交付同步保存到03-测试用例/需求专项（或已有等价位置），更新用例索引，并在04对应需求记录中关联来源与覆盖映射，无需再要求用户单独说“入库”。用户仅要求讨论测试点、举例或明确指定其他交付位置时，按本次要求处理，不擅自生成正式用例或搬迁文件。初稿标为待评审；项目不要求评审时沿用其设计状态，后续只依据实际确认或评审记录更新，不因生成或保存而自动视为已批准、已执行。复用用例保持引用，修订用例更新原件，避免同一正文重复保存；保存失败如实说明，不宣称已入库。

## 数据与结果

复用有效样本及数据准备方法，注明用途、核验时间和限制。区分本地数据、加工指标、缓存、外部接口及模拟响应，不假设改一个字段就能控制最终输入。

区分模拟演练、接口验证、完整业务联调及不同环境证据。设计完成、评审通过和执行通过分别记录；历史通过不继承到本轮。结果写入 04 对应需求报告或已有平台，证据归 05，不将本轮执行状态写进用例母版。

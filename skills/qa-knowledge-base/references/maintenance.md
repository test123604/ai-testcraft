# 持续维护

## 每轮先检查资料范围

按根README及用户最新指定的项目/业务范围筛选增量，再判断确认依据和复用价值。同一聊天涉及项目规则、个人OKR和通用AI方法时，只沉淀属于本项目的内容；范围外项跳过，不生成知识文章、待确认问题或缺口提醒。其他项目资料只在有指定归属及相应任务授权时更新到对应库，不因可访问就跨库搬迁。

项目需要的工具使用方法、上下游契约和特定交付约束可以保留必要说明与来源；工具程序、跨项目制度、绩效统计及Prompt/Skill本体在库外维护。知识库自身保留最小控制资料，不每天生成一套管理报告。实际评审与执行证据仍关联项目需求，不能因管理统计在库外就丢失测试依据。

用户明确要求清理范围外资料时，保留原件迁至用户指定或任务上下文可明确确定的库外位置，核实源目标路径、记录迁移映射并修复引用；不要只移到本库归档后继续计为项目知识。工具涉及现行调用者或调度任务时，在授权范围内适配依赖并验证；不能安全分离则保留原件并说明依赖，不删除、打断运行或声称迁移完成。普通读取、导入和用例设计不触发这类迁移。

## 自动判断沉淀价值，事实需要依据

采用“主动整理已确认内容，按需集中确认疑问”，不要求用户逐条指定入库。判断哪些内容值得复用、属于哪个主题，不替用户或业务方凭空确认事实。

写入前先提炼：后续测试能复用的规则/条件、操作或查询方法、已证实的原因、最终状态及适用边界。用这些结果替换原主题中的旧内容；不把发现、试错、重试、进度播报和被否定猜测逐段追加进知识正文。用户要的是知识结果时，详细排障过程不因发生在本项目就自动成为知识资产。

原始接口/数据库响应、运行日志、截图序列、浏览器快照、脚本/依赖、验证JSON和打包产物默认在用户指定库外工作区保存；只有主文档理解或验收必须依赖的少量附件才按项目约定纳入。保留最少来源、日期、环境/版本与证据位置即可，不重复生成索引、迁移报告或每日过程总结；维护记录只记一次实际变更和必要水位，不逐问答登记。没有可复用增量时不写入。

- 用户要求记入知识库时，即时处理指定内容。尚未确认的结论保存为待确认，保存动作不使它成为业务事实。
- 在已授权的维护任务中，检查指定来源新增和修订，将有复用价值的已确认规则、根因、核查方法、数据准备经验和覆盖缺口更新到对应主文档。
- 用户明确采纳、职责范围内的业务/开发确认、已完成评审和实际验证记录分别支持其范围内结论。实际结果证明相应观察，不独自证明业务验收预期正确；AI 建议、沉默、示例和计划不算确认。
- 普通分类、去重、引用修复、已确认且无冲突的更新直接执行。来源冲突、依据缺失或未经确认的验收预期变化，写入集中待确认，不阻塞独立更新。

待确认事项复用项目现有主文档的待确认章节或单一清单，记录问题、影响、现有依据、所需材料及对应角色，按主题去重。解决后链接到修订后的主文档；已报告且无变化的问题不反复提醒。

## 即时及定期运行

用户指定需求池为统一来源的同步任务，先按下一节处理来源及关联，再推进各自成功水位。

## 从需求池同步到在线知识库

用户指定需求池为统一来源时，“同步到知识库”表示更新入口和关联，不等于复制原文、重写用例或移动源需求。先核本人参与关系及知识库业务范围，按需求ID去重，读取工作项实际关联的需求文档、附件、测试用例和测试报告；不能仅按创建人、相近标题或旧映射猜配。只核了部分工作项，就只报告该部分同步完成，不声称全量历史同步。

- 每项需求集中展示可点击的需求池入口、原文链接、对应测试用例链接及其附件。验收范围、分析和测试方法放测试指南，不混作需求原文。
- 附件有可用的原链接就引用；没有可用链接才下载原件并放到所属需求下面，保留文件名与版本。不把临时签名下载地址当长期链接；下载、上传或权限失败标明缺失，不伪称已同步。
- 测试用例入口跟随需求当前实际关联，保留来源区别；未填写留空，不自动用本地设计稿或同名集顶替，不复制正文、修改用例状态或通过勾选。
- 报告区同步需求实际关联的原报告链接，保留标题和真实结论。即使原报告记的是免测、风控确认切流或后续巡查，也不能因分类判断漏掉用户指定的报告入口，更不能把它改成测试通过；环境和实际执行范围分别说明。
- 暂停的需求单独保留并注明状态来源，不与已上线需求合并、不自动恢复执行。Mock历史演练和真实test/生产验收分别判断。
- 更新前读取远端版本，保留人工修改；写后回读核对链接、附件归属和原件，修正同步基线。源工作项、原文、用例及报告保持不变，除非有单独修改授权。本地资料是否调整按本次范围决定，云端整理不自动触发本地迁移。

具体项目地址、需求ID、暂停事实和映射只记在项目自己的规则或库外同步配置中，不写入通用Skill或公开仓库。

## 调度与成功水位

Skill 本身不会持续运行。讨论定期维护不等于创建计划；只有用户要求配置计划时，明确资料源与访问范围、时间与时区、休息日规则和实际执行能力，再用可用调度工具落实，不只写一句“以后自动更新”。已有明确配置沿用，不重复询问。

不假设能读取全部成员聊天或私有数据。跨会话记录不可读时，使用用户指定的共享记录、评审结论或更新材料，不要求开放无关聊天。

每轮从上次成功处理位置开始，检查新增和修订，覆盖晚到的旧事项更新，不只按“昨天”过滤。复用用户指定的库外维护回执或团队已有记录，简记时间、改动位置、原因、遗留项和各来源成功处理位置。按来源记录游标、更新时间或材料版本即可，不另建重复台账。

成功位置只推进到确实检查并处理的范围；读取失败的来源保留原位置和待重试项，其他来源可独立推进，不宣称全部完成。无变化按原记录简记处理位置，不创建每日汇总文件。提醒遵循用户偏好，优先报告需要行动的问题。

## 按变化维护相关资产

| 触发 | 处理 |
|---|---|
| 新需求 | 关联来源，复用已有规则与用例，仅补差异 |
| 确认规则变化 | 更新当前规则及受影响用例、数据方法和工具说明，处理旧结论和索引 |
| 评审或执行发现遗漏/缺陷 | 修订原用例或必要增量，沉淀有证据的根因与方法；本轮结果留在报告 |
| 新人操作受阻 | 修正对应指南或数据方法的具体缺口 |
| 需求结束 | 可复用结论纳入主资料，保留原始来源与证据；结束不等于全部过时 |
| 重复、查找困难或失效链接 | 在相关范围清理和修复索引，不每轮全库清理 |

## 控制体积与检索范围

用户要求精简时，按检索任务合并：菜单/按钮归操作手册，流程/用例复用/异常覆盖归测试标准，规则/数据准备/状态/常见问题归业务问答，API/字段/分环境SQL归接口查询，代码证据归源码参考。这是可选职责映射，不强制所有项目保留五份文档；用户已确认的结构优先。合并需保留适用版本、来源、异常预期和未确认边界，不只拼接全文或删除难造数场景。

本地与在线知识库调整范围分别确认，沿用已有授权。需要对齐时以知识主题映射同步，不要求文件数一致：本地可保留图片、原始需求/用例和必要附件，平台已有需求/用例引用原链接。先备份并记录原路径、替代和哈希，重写相对链接与章节锚点；核对附件原字节、SQL/代码段和关键异常场景后移出旧衍生资料。同步前读远端版本，保护人工编辑，局部更新、回读后推进基线，不用旧本地目录全量覆盖云端。

目录迁移要同步修改日常检查程序、调度提示和项目协作入口，避免下轮恢复旧目录。维护记录及同步水位复用用户指定位置；若用户要求过程留在库外，不为满足模板另建库内台账。Skill只存通用整理方法，具体文件/云端映射与环境信息留在项目资料或库外工具配置。

- 默认更新原主题。只有现有文档无法承载的新主题、独立交付物或需独立追溯的证据才新增文件；普通问答、临时进度和重复过程不单独成文。
- 一条当前规则只维护一处正文，其他材料引用及说明差异。成熟的需求专项用例迁入回归库时保留 ID/来源，不维持两份正文；可复用设计与已验证基线分别标识。
- 文档混入独立主题或难以定位时，先合并重复、移出历史过程，再按需拆分并修复入口。不以固定文件数、字数和用例数清理，不删必要规则、步骤和异常预期来缩短篇幅。
- 索引只保留定位所需的 ID/标题、路径或链接、模块/关键词、适用范围和状态。复用平台已有字段，增量更新，不维护每篇正文的第二份摘要全文。规则与指南按需要注明来源、确认角色、核验日期和复核条件。
- 旧结论在同轮更新中明确被替代关系，避免不断追加矛盾段落。并行有效版本或不同环境规则可同时有效，不按日期老旧一律归档。
- 用户已授权删除的已合并旧稿、重复副本和无用生成物，核对替代、引用及目标路径后直接清理；不要为每次合并再在知识库归档一份维持同样体积。唯一原件、执行依据和有恢复用途的备份按用户保留约定处理，不能把“只留结果”误解为丢失唯一证据或擅自删除原始需求/用例。需留存的原件退出日常知识目录，正文不复制它的全文。
- 清理历史用例时读前置、步骤和预期，按是否有独有场景、可复用异常、有效版本或执行依据判断。被现行用例覆盖且没有独有价值的旧副本，在用户授权范围内删除并修复引用；有独有价值的保留为专项设计并标适用状态。不能只因“旧版”、格式相同、数量多或需求暂停删除，也不把难造数的异常场景当无用。唯一手写原件和执行证据按用户保留约定移出日常库，避免公开或永久丢失。
- 待确认内容独立标识，不作默认预期；历史证据和被替代材料退出日常检索，保留定向追溯。归档遵循团队保留要求并修复引用；失效链接如实标记并寻找授权来源，不凭空补内容或删除证据。
- 使用 Git 历史追溯普通修订，避免“最终版2、备份”等副本。发布基线和原始证据按实际追溯需要保留。内部和大体积材料留在团队授权存储并说明访问权限，公开仓库只含通用 Skill、模板和公开示例。
- 维护记录不复制正文，按团队留存规则滚动归档。没有新知识时不新增知识文档。

检索变慢或命中错误时，记录具体任务、范围、人工查找时间及遗漏，先修复索引、重复冲突、范围和访问能力问题；数据量与实际需要支持时再引入全文检索服务，不默认建设新平台。

## 完成检查

检查本轮来源、链接、重复、相关用例和索引，简短说明更新位置、影响资产、待确认及未执行的检查；实际执行状态与知识维护结果分开反馈。

# 建库与资料归属

## 固定五类目录

首次创建根目录、五个一级目录及有实际导航内容的根 README。下列业务文档和子目录仅在有资料或任务需要时创建，不预生成空文件和占位用例。

```text
项目测试知识库/
├── README.md
├── 01-项目与业务/
│   ├── 项目概览.md
│   └── 业务规则.md
├── 02-测试指南/
│   ├── 新人上手.md
│   ├── 标准测试流程.md
│   └── 环境与数据准备.md
├── 03-测试用例/
│   ├── README.md
│   ├── 常用回归/
│   ├── 专项回归/
│   └── 需求专项/
├── 04-需求与交付/
│   └── 需求标识或名称/
└── 05-支撑资料/
    ├── 参考资料/
    ├── 工具/
    ├── 证据/
    ├── 维护/
    └── 归档/
```

| 位置 | 唯一职责 |
|---|---|
| 根 README | 项目、五类入口、团队约定或等价目录映射；不复制业务规则 |
| 01-项目与业务 | 业务链路、系统边界、术语、角色；已确认规则的条件、状态、结果和依据 |
| 02-测试指南 | 新人路线、接需求到交付的标准流程、可重复使用的环境与数据准备方法 |
| 03-测试用例 | 唯一用例正文及定位索引；保持项目主格式和编号，常用回归经过筛选，专项按影响选择，需求专项承载增量 |
| 04-需求与交付 | 按需求关联原始材料、覆盖映射、所选用例、本次报告及缺陷；引用 03 正文和平台明细 |
| 05-支撑资料 | 接口、代码入口、架构引用、工具说明、原始证据、维护及归档；当前业务结论和方法分别回到 01、02 |

待确认事项集中在 `05-支撑资料/维护/待确认事项.md`，其他位置引用。证据按需求或任务、环境和执行批次定位。用例索引记录 ID、链接、适用场景和设计成熟状态，不把全部专项作为每轮必测。

受平台约束无法使用标准目录名时，在根 README 保留等价映射，保持职责一致。已有库只在明确要求整理结构时进行迁移，其他任务按映射访问。

## 首次交互顺序

1. 先问：“你希望把知识库建在哪个目录下？请提供目标路径。”如果只提供父目录，再明确项目根目录名和最终路径。已有明确位置不重复询问；位置未明确不自行选址，也不提前扫描资料。
2. 检查目标，在指定位置创建根目录、五类目录和导航 README；同名目录和文档检查后复用，不覆盖现有内容或建立重复结构。实际验证目录可用，失败说明原因。
3. 目录建好后再问：“知识库目录已建好。需要整理的资料在哪里？可以提供文件、文件夹路径或在线文档链接。”资料已提供则直接处理，支持分批补充。没有资料说明仅完成目录骨架。
4. 读取指定材料及必要引用，按正文判定项目、模块、用途和环境/版本。业务归 01，方法归 02，用例归 03，需求与报告归 04，接口、工具和原始证据归 05。未读取、无法解析和权限不足分别记录；冲突或来源不明进入待确认。
5. 写入前检查已有主题和来源。完全重复引用原件，相关内容合并主文档，不同版本保留关系。一份混合材料原件仅存一处，提炼内容注明出处。库外源文件默认保留，只有用户要求迁移才移走；不擅改原件或覆盖同名不同内容。在线资料优先引用，任务需要时保存带来源与版本的快照。
6. 更新同一份 `05-支撑资料/维护/导入清单.md` 及必要索引，记录来源、目标和处理结果，必要时注明未读/冲突原因。平台已有同等清单则直接复用。迁移记录原位置到新位置的映射并修复引用，避免两套正文同时维护。用例保留 ID、主格式及历史执行范围，导入不等于本轮执行通过。不为每批资料生成总结文件。
7. 检查指定资料均有处理结果，已读内容归属明确，来源与链接可定位，重复、冲突和缺失如实列出。反馈目录位置、已整理范围和待补材料，不要求一轮补全所有知识，也不补造业务内容。
